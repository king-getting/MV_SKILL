# reading.json 字段

模型写给脚本读的**结构化解读**。`reading.py render` 会校验必填项，缺了直接报错——这是刻意的：没有证据的解读不该被渲染出来。

```jsonc
{
  "title": "歌名 — 歌手",
  "theme": {
    "one_line": "一句话主题。必须只有这首歌能这么说。",
    "evidence": [                       // 至少 2 条
      { "line": "L16", "t": 68.05, "quote": "我多想 能多陪你一场" }
    ]
  },
  "narrative": {
    "pov": "第二人称倾诉",              // 谁在说
    "addressee": "一个不在场的人",       // 对谁说；不确定就写两种可能
    "mode": "将来时的愿望 + 过去时的叙述",
    "summary": "一段 100–200 字的叙述概括，不要复述歌词",
    "arc": [{ "act": "起", "sections": ["S1", "S2"], "turn": "这一幕发生了什么" }]
  },
  "emotion": {
    "curve": [                          // 每段一条，和 emotion.json 对得上
      { "section": "S2", "t": 29.94, "arousal": 0.44, "valence": -0.34,
        "why": ["亮度升到 0.59", "人声覆盖 97%"] }
    ],
    "turns": [{ "t": 107.5, "what": "40 秒器乐进来，词断了" }]
  },
  "imagery": [
    { "id": "灯火 / 城市", "lines": ["L07", "L09"], "function": "越亮越慌，光不是安慰而是尺度" }
  ],
  "rhetoric": [
    { "device": "未完成式", "note": "全篇没有一个完成时", "examples": ["我多想 能多陪你一场"] }
  ],
  "sonic": {
    "key": "C minor（置信度 1.0，只当倾向）",
    "notable": [{ "what": "几乎没有打击点", "t": null, "why": "起音密度 2.7–3.4/s" }],
    "arrangement_arc": "靠亮度而不是音量推进"
  },
  "atmosphere": {
    "temperature": "冷到暖", "space": "间奏后打开", "density": "疏→密→疏",
    "light": "钨丝灯与夜色", "palette": ["#0B1622 夜青"]
  }
}
```

## 什么算合格证据

| 合格 | 不合格 |
|---|---|
| `{line: "L16", t: 68.05, quote: "我多想 能多陪你一场"}` | `"歌词表达了想陪伴的愿望"` |
| `why: ["亮度 1.00（全场最亮）", "valence 归零"]` | `why: ["情绪很激动"]` |
| 一个段落只在某个重复里出现的变化（"第三遍比第一遍亮 0.30"） | "整首歌都很悲伤" |

**替换测试**：把这句判断里的歌名换成任何另一首歌，句子还成立吗？成立就删。

## 三个必须用上的字段

- `repeats`：同一段落的逐次差额（arousal/brightness/energy）。歌曲的推进常常藏在这里，而不是段落之间。
- `silent_gaps`：无词区间。它通常就是"失语""留白""转折"的位置，而且有精确秒数。
- `why`：`emotion.json` 已经算好的证据短语，直接引用，不要自己编形容词。

## 常见毛病

| 毛病 | 改法 |
|---|---|
| 把 arousal 当情绪强度下结论 | 只说"比上一段高 0.13，主要来自亮度和密度" |
| 逐句复述歌词 | 引用 1–2 句当证据，其余用概括 |
| 主题一句话能套在三万首歌上 | 找到只有这首歌才有的那个转折：并置、反问、人称、时态 |
| 忽略器乐段 | 无词段落往往是解读的钥匙（失语/退潮/换气） |
| 断言调性 | 置信度 < 0.5 就写"倾向"，不写"是" |
